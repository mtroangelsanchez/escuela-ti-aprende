Dominio 1: Conceptos de la nube (24 %)

Cerca de 16 de las 65 preguntas. Es el dominio "de vocabulario": si dominas los términos, son puntos fáciles.

1.1 Valor de la nube de AWS

Seis ventajas de la computación en la nube

VentajaIdea clave
Cambiar CapEx por OpExNo compras hardware por adelantado, pagas lo que consumes
Economías de escalaAWS agrega el uso de todos sus clientes y baja los precios
Dejar de adivinar la capacidadEscalas hacia arriba o abajo según la demanda real
Mayor velocidad y agilidadRecursos en minutos, no en semanas
Dejar de gastar en operar centros de datosTe enfocas en tu negocio, no en racks y cableado
Despliegue global en minutosVarias Regiones con pocos clics

Conceptos que se confunden

  • Elasticidad: crecer y reducir recursos automáticamente según demanda.
  • Escalabilidad: capacidad de manejar más carga (vertical: más grande; horizontal: más instancias).
  • Alta disponibilidad: el sistema sigue funcionando ante fallos (varias AZ).
  • Tolerancia a fallos: sigue operando aun cuando falla un componente, sin interrupción.
  • Agilidad: velocidad para experimentar y lanzar.

1.2 Infraestructura global de AWS

  • Región: ubicación geográfica con varias AZ. Eliges Región por: cumplimiento y residencia de datos, latencia, costo y disponibilidad de servicios.
  • Zona de Disponibilidad (AZ): uno o más centros de datos con energía, red y refrigeración redundantes. Aisladas entre sí, conectadas con baja latencia.
  • Edge locations: sitios de la red de entrega de contenido (CloudFront) y Route 53, más cerca del usuario.
  • Local Zones / Wavelength / Outposts: extienden AWS más cerca de usuarios o a tu centro de datos.
  • Regla de oro: para alta disponibilidad usa varias AZ; para recuperación ante desastres o latencia global usa varias Regiones.

1.3 AWS Well-Architected Framework (6 pilares)

  1. Operational Excellence (excelencia operativa): ejecutar y monitorear, mejorar procesos.
  2. Security (seguridad): proteger datos y sistemas.
  3. Reliability (fiabilidad): recuperarse de fallos, cumplir la demanda.
  4. Performance Efficiency (eficiencia del rendimiento): usar recursos de forma eficiente.
  5. Cost Optimization (optimización de costos): evitar gasto innecesario.
  6. Sustainability (sostenibilidad): minimizar el impacto ambiental.

Herramienta: AWS Well-Architected Tool. Truco: "Scalability" NO es un pilar.

Principios de diseño en la nube

Diseñar para fallos, desacoplar componentes, implementar elasticidad, tratar la infraestructura como código, pensar en seguridad en cada capa.

1.4 AWS Cloud Adoption Framework (AWS CAF)

Seis perspectivas: Business, People, Governance (negocio) y Platform, Security, Operations (técnicas).

1.5 Estrategias de migración (las "6 R")

EstrategiaSignificado
RehostLift-and-shift, mover sin cambios
ReplatformPequeños ajustes sin rediseñar (lift-tinker-and-shift)
RepurchaseCambiar a SaaS / otro producto
Refactor / Re-architectRediseñar para aprovechar la nube
RetireApagar lo que ya no se necesita
RetainDejar donde está por ahora

Servicios de migración: AWS Migration Hub, Application Migration Service, Database Migration Service (DMS), Snow Family (transporte físico de datos).

1.6 Modelos de implementación y de servicio

  • Nube pública, privada (on-premises) e híbrida.
  • IaaS (EC2, VPC, EBS): administras SO y aplicaciones.
  • PaaS (Elastic Beanstalk, RDS): administras aplicación y datos.
  • SaaS (Amazon Chime, WorkMail): usas el software terminado.

1.7 Economía de la nube

  • TCO (costo total de propiedad): comparar costo on-premises vs nube (herramientas: Pricing Calculator, Migration Evaluator).
  • Costos de licencias, mano de obra y tiempo de comercialización forman parte de la comparación.
  • El costo operativo baja al usar servicios administrados y serverless.

Dominio 2: Seguridad y cumplimiento (30 %)

Cerca de 19 preguntas. Dominio con más trampas de "¿quién es responsable de qué?".

2.1 Modelo de responsabilidad compartida

  • AWS: seguridad DE la nube. Instalaciones físicas, hardware, red global, hipervisor, software de servicios administrados.
  • Cliente: seguridad EN la nube. Datos, IAM, SO invitado y parches (en EC2), firewall (security groups), cifrado, configuración.
ServicioAWS administraCliente administra
EC2 (IaaS)Hardware, hipervisorSO invitado, parches, apps, security groups, datos
RDS (administrado)SO, parches del motor, respaldosDatos, accesos, parámetros, red
S3 / DynamoDBInfraestructura, durabilidadPermisos, cifrado, clasificación de datos
LambdaSO, runtime, escaladoCódigo y permisos

Controles heredados: seguridad física. Controles compartidos: gestión de parches, configuración, capacitación. Específicos del cliente: zonas de cumplimiento de datos propias.

2.2 IAM (Identity and Access Management)

  • Usuario: identidad con credenciales a largo plazo. Grupo: conjunto de usuarios. Rol: identidad con credenciales temporales (servicios, otras cuentas, federación). Política: documento JSON de permisos.
  • Mínimo privilegio: solo los permisos necesarios.
  • Usuario raíz (root): activa MFA, no lo uses a diario, no crees claves de acceso para él.
  • MFA, políticas de contraseñas y rotación de claves.
  • Rol de IAM para EC2 en lugar de guardar claves en la instancia.
  • IAM Identity Center: inicio de sesión único (SSO) para múltiples cuentas y apps.
  • AWS Organizations + SCP: límites de permisos para cuentas de la organización.
  • Amazon Cognito: identidad de usuarios finales de tus aplicaciones.

2.3 Protección de datos

  • Cifrado en reposo y en tránsito. AWS KMS administra claves; CloudHSM ofrece HSM dedicado.
  • AWS Certificate Manager (ACM): certificados TLS/SSL.
  • AWS Secrets Manager: guarda y rota secretos. Parameter Store: parámetros y configuración.
  • Amazon Macie: descubre datos sensibles (PII) en S3.

2.4 Seguridad de red

  • Security groups: firewall con estado a nivel de instancia, solo reglas "permitir".
  • Network ACL (NACL): firewall sin estado a nivel de subred, permite y deniega.
  • AWS WAF: bloquea ataques web (SQL injection, XSS).
  • AWS Shield: protección DDoS (Standard gratis; Advanced de pago).
  • AWS Firewall Manager: administra reglas de WAF/Shield entre cuentas.
  • VPN y Direct Connect: conectividad privada.

2.5 Monitoreo, detección y auditoría

ServicioPara qué
CloudTrailRegistra llamadas a la API (quién, qué, cuándo)
CloudWatchMétricas, logs y alarmas
AWS ConfigHistorial y cumplimiento de configuraciones de recursos
GuardDutyDetección de amenazas inteligente
InspectorEscaneo de vulnerabilidades (EC2, ECR, Lambda)
Security HubVista centralizada de hallazgos de seguridad
DetectiveInvestigar la causa de un hallazgo
Trusted AdvisorRecomendaciones de costo, seguridad, rendimiento, límites y tolerancia a fallos
Amazon MacieDatos sensibles en S3

2.6 Cumplimiento y gobernanza

  • AWS Artifact: reportes de cumplimiento (SOC, ISO, PCI) y acuerdos (BAA) de descarga.
  • AWS Audit Manager: automatiza la recolección de evidencia para auditorías.
  • Cumplimiento por Región: los datos no salen de la Región a menos que tú lo decidas.
  • AWS Control Tower: configura una landing zone multicuenta con barreras de protección.

2.7 Otros recursos de soporte de seguridad

  • AWS Security Blog, Knowledge Center, Security Bulletins, AWS Support.
  • Informar abuso o actividad sospechosa: AWS Trust & Safety / abuse report.
  • Pruebas de penetración: permitidas en ciertos servicios sin aprobación previa, siguiendo la política vigente.

Trampas frecuentes

  • "Parchear el SO de EC2" = cliente. "Parchear el SO de RDS" = AWS.
  • Security group = stateful; NACL = stateless.
  • CloudTrail = auditoría de API; CloudWatch = monitoreo.
  • Artifact = reportes de cumplimiento, no escaneo de vulnerabilidades.

Dominio 3: Tecnología y servicios de la nube (34 %)

Cerca de 22 preguntas. Es el dominio más grande: aprende para qué sirve cada servicio en una frase.

3.1 Métodos de implementación y operación

  • Consola de administración (web), AWS CLI (línea de comandos), SDKs (código), APIs.
  • Infraestructura como código: CloudFormation (plantillas), CDK (código).
  • Elastic Beanstalk: sube tu código y AWS aprovisiona el entorno.
  • Systems Manager: operación y administración de flotas de instancias.

3.2 Infraestructura global (repaso)

Regiones, AZ, edge locations; CloudFront, Global Accelerator (ruta de red optimizada), Route 53.

Opciones de compra de EC2: On-Demand, Savings Plans, Reserved, Spot, Dedicated Hosts/Instances, Capacity Reservations (ver Dominio 4).

3.6 Redes y entrega de contenido

  • VPC: red virtual aislada. Subredes públicas/privadas, Internet Gateway, NAT Gateway, tablas de rutas.
  • Security groups / NACL: control de tráfico.
  • VPN Site-to-Site: túnel cifrado por Internet. Direct Connect: enlace dedicado privado.
  • Route 53: DNS y enrutamiento (latencia, geolocalización, conmutación por error).
  • CloudFront: CDN. API Gateway: crear y publicar APIs. Transit Gateway: unir muchas VPC y redes.

3.7 Integración de aplicaciones

  • SQS: cola de mensajes (desacoplar). SNS: notificaciones pub/sub. EventBridge: bus de eventos. Step Functions: orquestar flujos.

3.8 Analítica

  • Athena: consultas SQL sobre S3. Glue: ETL. Kinesis: datos en streaming. QuickSight: BI y dashboards. EMR: big data (Hadoop/Spark). OpenSearch: búsqueda y logs.

3.9 Inteligencia artificial y machine learning

  • SageMaker: construir, entrenar y desplegar modelos de ML.
  • Bedrock: modelos de base (IA generativa) vía API.
  • Rekognition: imágenes y video. Comprehend: procesamiento de lenguaje natural. Lex: chatbots. Polly: texto a voz. Transcribe: voz a texto. Translate: traducción. Textract: extraer texto de documentos. Kendra: búsqueda empresarial. Amazon Q: asistente generativo.

3.10 Gestión y gobierno

  • CloudWatch, CloudTrail, Config, Trusted Advisor, Systems Manager, Organizations, Control Tower, Service Catalog, Health Dashboard (estado de servicios y eventos que afectan tu cuenta).

Dominio 4: Facturación, precios y soporte (12 %)

Cerca de 8 preguntas. Es el dominio más pequeño, pero muy "puntuable" porque es memorizable.

4.1 Modelos de precios

  • Pago por uso (pay-as-you-go), pagar menos al reservar, pagar menos al usar más (precios por volumen).
  • Capa gratuita (Free Tier): tres tipos: siempre gratis, 12 meses gratis, pruebas de corta duración.

Opciones de compra de EC2

OpciónIdeal paraDescuento
On-DemandCargas cortas, impredeciblesNinguno, sin compromiso
Savings PlansUso constante, compromiso de $/hora a 1 o 3 añosHasta ~72 %
Reserved InstancesUso estable de una configuración concreta, 1 o 3 añosHasta ~72 %
SpotCargas tolerantes a interrupcionesHasta ~90 %
Dedicated HostsLicencias por socket/núcleo, cumplimientoSegún opción
Capacity ReservationsGarantizar capacidad en una AZSin descuento por sí solo

Qué influye en el costo

  • Cómputo (tipo, tiempo), almacenamiento (volumen y clase), transferencia de datos.
  • Entrada de datos desde Internet: gratis. Salida a Internet y entre Regiones: se cobra. Entre AZ: puede cobrarse.

Meta de preparación

  • Simulacros consistentes por encima de 80 % antes de presentar (margen sobre el 70 % de aprobación aproximado).
  • Cada pregunta fallada se registra: tema, motivo del error (concepto, lectura, prisa) y servicio relacionado.

Estrategia durante el examen

  1. 65 preguntas en 90 minutos: ~1 min 20 s por pregunta. No te atores.
  2. Marca para revisar las dudosas y avanza.
  3. Descarta primero las opciones claramente incorrectas.
  4. Lee con cuidado las palabras clave: "más económico", "menor esfuerzo operativo", "administrado", "serverless", "alta disponibilidad".
  5. En las de selección múltiple ("Seleccione DOS") marca exactamente la cantidad pedida. Se califica todo o nada.
  6. Responde todas: no hay penalización por respuestas incorrectas.
  7. 15 de las 65 preguntas no cuentan para tu puntaje (son de prueba) y no sabrás cuáles, así que trata todas por igual.

Día del examen

  • Identificación válida, llegar o conectarte 30 minutos antes. Si es en línea (Pearson VUE OnVUE), prueba tu equipo y revisa el entorno.
